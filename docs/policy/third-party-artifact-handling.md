# Third-party artifact handling

The repository is public. Every byte committed to it is published to anyone who
looks, and stays published — a later deletion does not un-fetch a clone.

So the rule is a default rather than a judgement
([ADR 0083](../adr/0083-third-party-bytes-are-never-redistributed-by-fpbench.md)):

```
DO NOT VENDOR
```

It holds even where upstream is MIT, BSD or Apache. The question "may we commit
this checkpoint?" has one project-level answer, so it does not get asked once per
algorithm.

## What the repository holds

```
+ acquisition code
+ upstream URLs and identifiers
+ commit SHAs
+ exact versions
+ SHA-256 digests
+ expected byte sizes
+ configuration
+ dependency locks
+ artifact metadata
+ provenance records
+ project-written integration glue
+ generated evidence
```

## What it never holds

```
- a copy of an upstream repository
- model weights
- a checkpoint
- a runtime bundle
- a compiled upstream binary
- a dataset
- fingerprint images
- extracted embeddings
- an upstream archive
```

## The local artifact store

Everything in the second list lives outside the working tree:

```
~/.cache/fpbench/third_party/
    sourceafis/
    nbis/
    flx/
    ...
```

or under a root chosen with:

```
FPBENCH_THIRD_PARTY_ROOT
```

The repository knows four things about each artifact — a role, an expected
digest, an expected size, and an upstream identity — and never an absolute path.
A manifest carrying one would be a manifest that worked on one machine; the same
manifest has to work on the Windows checkout, in WSL, and on a runner that will
never have the file at all.

`fpbench.third_party.artifacts` resolves a placement into a path at runtime, and
refuses a store root inside the repository: a store there is one `git add -A`
away from publishing a checkpoint. Verification checks size first and digest
second, so a truncated download is reported as truncated rather than as "the
wrong file".

## Upstream source is a runtime artifact too

This is the part that surprises people. An upstream *repository* is acquired
exactly like a checkpoint:

```
official upstream repo
        |
        v
   exact pinned commit
        |
        v
   local acquisition
        |
        v
  digest verification
        |
        v
local immutable source bundle
        |
        v
     fpbench wrapper
```

rather than copied into `integrations/<name>/vendor/`. It improves provenance and
it shrinks the licensing surface at the same time.

## Changing upstream source

A ladder, tried in order:

```
1. a wrapper that changes no upstream byte
        |  if impossible
        v
2. a project-owned transformation recipe
        |  if impossible
        v
3. a local patch
```

For rungs two and three the repository stores a recipe, not source:

```
preimage digest
transformation rule
postimage digest
reason
classification: integration_only
```

A reviewer can see exactly what was done and confirm the result reproduces; a
reader of the public repository still receives no upstream code. `INTEGRATION_ONLY`
is the only classification this policy permits without further argument —
anything that could move a score is `BEHAVIOUR_AFFECTING`, and that is an ADR
before it is a commit
([ADR 0064](../adr/0064-preprocessing-is-part-of-the-algorithm.md)).

## Enforcement

`.gitignore` is a convenience. It stops accidents matching patterns somebody
thought of, says nothing about `git add -f`, and has no opinion about what is
already tracked.

The enforcement is `fpbench.third_party.repository_guard`, which reads what Git
**actually tracks** and applies eight rules:

| rule | catches |
|---|---|
| `model_weight_extension` | `.pt`, `.pth`, `.pyt`, `.ckpt`, `.safetensors`, `.onnx`, `.h5`, `.npz`, `.bin`, `.pkl`, … |
| `known_checkpoint_filename` | `best_model.pyt`, `pytorch_model.bin`, `model.safetensors`, … |
| `runtime_bundle_or_binary` | `.so`, `.dll`, `.dylib`, `.jar`, `.class`, `.exe`, … |
| `source_or_artifact_archive` | `.zip`, `.tar.gz`, `.whl`, `.7z`, … |
| `dataset_or_biometric_image` | `.png`, `.pgm`, `.wsq`, `.tif`, `.xyt`, `.an2`, … |
| `forbidden_third_party_path` | `vendor/`, `third_party/`, `upstream/`, `weights/`, `checkpoints/`, … |
| `known_upstream_artifact_digest` | the exact bytes of every upstream artifact this project pins |
| `oversized_tracked_file` | anything over one megabyte |

There is exactly one exception, listed by name rather than by pattern: the ten
synthetic imaging fixtures under `tests/fixtures/imaging/`. They are
checkerboards, gradients and ridge-shaped stripes generated by `generate.py` in
that directory; no subject produced them, and their golden hashes are what proves
the canonical transform still produces the pixels it produced before. An
eleventh file appearing there is a finding.

## CI

Three further rules, scanned for by token in every workflow file:

**CI downloads no restricted artifact.** The public jobs verify contracts,
manifests, digests-as-metadata, synthetic fixtures, source structure and
evidence. Artifact-present verification is a local operation.

**CI uploads no third-party bytes.** No workflow may upload a checkpoint,
upstream source, model output, fingerprint imagery, descriptors or a runtime
bundle as a CI artifact — including from a failing job. Only fpbench-owned
diagnostic text, which contains none of those bytes.

**No public container image contains upstream artifacts.** A `Dockerfile`
describing how to build a runtime is fine. An image holding weights, restricted
source or a dataset is not published to any registry under this policy.
